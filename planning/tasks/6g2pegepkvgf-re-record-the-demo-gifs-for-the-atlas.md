# Re-record the demo GIFs for the atlas

## Objective

`assets/tui.gif` was last recorded 2026-07-21, a month before the atlas existed. The
README now opens by describing the atlas as the landing screen when `ui` is launched
outside a planning repo — and the demo directly beneath that sentence shows a TUI with no
atlas in it. For a release whose headline is multi-space planning, the hero asset argues
against the copy.

The wrinkle that makes this more than a `just gifs` run: every existing tape records
against `assets/demo-planning/`, a single planning tree. An atlas has nothing to show
with one space. This needs a throwaway multi-space registry, which is new ground for the
fixture setup — `picker.tape` is the closest prior art, since it already works on a copy
in `/tmp` to avoid dirtying the committed tree.

## Acceptance criteria

- [ ] A tape records the atlas: several cards, a logical space with more than one entry
  point (`h`/`l` selecting between a direct checkout and a pointer), `o`/`O` reordering,
  and `⏎` entering a space — the reversible navigation is the point, so the recording
  must return to the atlas and enter a second space.
- [ ] It runs against a throwaway registry via `TSKFLW_CONFIG_HOME`, built in `/tmp` by
  the tape itself, so the committed fixture and the recorder's real `spaces.toml` are both
  untouched. Re-running `just gifs` twice in a row produces the same result.
- [ ] At least two demo planning trees exist to register. Decide and record whether the
  second is a committed sibling fixture or generated by the tape; a generated one keeps
  the repo small but has to be populated enough that its card shows real counts.
- [ ] `assets/tui.gif` is re-recorded against current code either way — its glyphs, footer
  hints, and top rail have all changed since July, independently of the atlas.
- [ ] The README embeds the atlas GIF where the multi-space section describes it, and
  `assets/vhs/README.md` documents the registry fixture alongside the existing notes on
  `demo-planning` and the `picker` throwaway-copy pattern.
- [ ] Recorded at the same `FontSize`/`Width`/`Height`/`Theme`/`Padding` as `tui.tape`, so
  the READMEs stay visually consistent.

## Out of scope

- Re-recording `status`, `audit-show`, `picker`, `epic-show`, or `task-list` beyond what
  changed rendering forces. This task is the atlas plus the stale hero.
- A `status --all` GIF. The cross-space CLI view is worth showing eventually, but the TUI
  atlas is the release headline.
- Automating GIF regeneration in CI. `vhs` is deliberately not a build or runtime
  dependency (see `assets/vhs/README.md`).

## Implementation notes (2026-08-22)

Both GIFs are re-recorded. `assets/atlas.gif` is new; `assets/tui.gif` replaces the
2026-07-21 recording, which predated both the top-rail space chip and the `a atlas`
footer hint.

**The fixture answer was "committed sibling", plus a third tree the task did not
anticipate.** An atlas card is a planning *identity*, not a directory, so demonstrating
`h`/`l` entry-point selection needs two registered paths sharing one durable id — not
just two trees. Hence `demo-bike-shop/`, an impl repo that is a config file and nothing
else, pointing at `demo-planning/`. `demo-planning` also had no durable `id` at all
(`config migrate` minted one); without it the registry cannot group entry points and the
atlas would have rendered three unrelated cards.

`vhs/atlas-setup.sh` stages the registry rather than a tree, because that is what the
atlas reads. It is sourced, not executed — it has to hand back a cwd and an environment —
which made `set -euo pipefail` at file scope a real hazard: `set -e` leaking into the
recording shell would kill the take on the first non-zero command. Strict mode is confined
to a staging subshell.

**A rendering inconsistency only visible in the recorded frames.** The landing atlas
showed a green `current` badge on the seeded space while the top-rail chip read `[atlas]`
— the same frame claiming both that no space was chosen and that one was. `renderBody`
now passes the zero workspace until `spaceChosen`, so no card is marked until the user
picks one. Pinned by `TestAtlasMarksNoCardCurrentUntilASpaceIsChosen`; the pre-existing
`TestAtlasLoadsGroupedCardsAndNavigatesThroughSelectedEntry` had its `current` assertion
moved to after an actual open rather than deleted.

Content came from two subagents: two research docs in the bike tree (cable-actuated disc
brakes; powder coating a previously painted frame — the latter argues against the epic it
sits beside, which is what makes a fixture look authored rather than generated), and the
whole `demo-kitchen` tree (3 epics, 24 tasks across every status, one open audit spanning
5 finding bands, 2 research docs).

Left deliberately: the kitchen tree's dates all read "today" against the bike tree's
"1mo ago". `updated_at` is auto-stamped and the tool correctly refuses to set it, and
`demo-planning/README.md` already documents that baked-in dates age until GIFs are
re-recorded. The contrast also reads as honest — one space touched last month, one in
active use.

Validation: both GIFs inspected frame-by-frame rather than assumed; `lint` clean in all
three fixture trees; `doctor` reports linkbacks consistent; `go test -race ./...`,
`golangci-lint run ./...`, planning lint, generated docs, and `git diff --check` clean.
The recorder's real `spaces.toml` was diffed against a backup after every staging run and
is byte-identical.
